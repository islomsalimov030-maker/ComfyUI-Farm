## 0. Резюме (главное)

1. **RefMod — это готовые латенты референсов, которые дописываются в `minimax_refs` после текстового кодировщика. Модель их видит, Qwen-кодировщик не видит.** В штатном ref2va картинка идёт в оба места: Qwen видит её под меткой `<Picture N>`, DiT получает латент [код S3]. `Apply` повторяет только вторую половину [код S1]. Поэтому в промпте нельзя сослаться на мод, а описание персонажа словами — единственный мост между текстом и модом. Это объясняет наш раунд B/C: мод лица давал небольшой эффект. **Есть готовые ноды, которые возвращают первую половину**: `H3 RefMod Text Encode` (H3Mod, экспериментальная) и `MiniMax H3 RefMods to Video` (Picker) показывают мод Qwen под меткой `<Picture n>` / `<Video n>` [док S1, S2]. Для раунда D без LoRA и без листа это главная новая ось. В, С (на качество не проверено никем).
2. **`concept_type` — только метаданные, на извлечение не влияет** [код + док S1]. Влияют режим (Full / Compressed), `ref_resolution`, маска, `max_tokens`. Наш выбор `clothing` / `background` — для учёта и `prompt_hint`, не для качества. В.
3. **Мод из N картинок — это один «видео»-референс из N кадров, а не N картинок** (`kind = video`, кадры склеены по времени) [код S1]. В штатном ref2va разрешено ≤ 9 картинок и ≤ 3 видео, всего ≤ 12 файлов [док S4]. В нашем слоте раунда D (лицо, тело, одежда, зона + плита) **4 видео-референса — больше штатных трёх**. Как модель ведёт себя вне этого распределения, никто не мерил. С (факт) / Н (последствия).
4. **Сила — не вес внимания**: `strength × retention` смешивает латент с его размытой копией (`w·z + (1−w)·blur(z)`) [код + док S1]. При 0.4 остаются палитра и крупная форма, деталь лица теряется. Выше смысла «силы» дают состав картинок и `copies` (каждая копия — полная цена в токенах). Пресеты retention 1.0 / 0.7 / 0.4 / 0.15 повторяют официальные маркеры H3 `fully_preserved / partially_preserved / attribute_transfer / weak_reference` [док S5]. В.
5. **Маска не вырезает фон, а размывает его** (`background_retention` 0 = полное размытие) [код S1]. Чистить фон надо в самих картинках, как делает наш `clean_bg`. Это подтверждено нашим раундом A. В.
6. **Масштаб и рост мод не передаёт**: в коде нет ничего о масштабе, у картинок на нейтральном фоне нет ориентиров роста [код S1], и наши s2_scale / s2_cap это подтвердили [наше]. Для Саманты (230 см) рост может прийти только из плиты (силуэт или метка головы) или текста. Пропорции и мускулатуру как форму тела мод передать может: это видимая форма, а не масштаб. Но цифр нет. С (масштаб) / Н (мускулатура).
7. **Пакет H3Mod заморожен**: автор приостановил разработку 15.10.2026 [S6]. Код MIT, рабочий. Коммит `517e8c4` зафиксировать и самим не ждать фиксов. В.

## 1. Как это устроено (только то, что влияет на подготовку)

| механика | факт | источник |
|---|---|---|
| режимы | `Full Reference` (`encode`) — латент VAE как есть; `Compressed Reference` (`training`) — пул в сетку `pool_h×pool_w` + MSE-дотяжка к полному латенту. Обучения нет: ни DiT, ни распознавателя лица, ни текста | [код+док S1] В |
| умолчание | у ноды Create по умолчанию **Compressed 16×16, 500 шагов**. Для лица автор сам предупреждает: «pooling averages away exactly the detail that carries a face», нужен `encode` или сетка 32×32+ | [код S1] В |
| `ref_resolution` | короткая сторона в px, **только уменьшение**, стороны → кратные 32. Штатный ref2va: `match` = площадь генерации, `max` = 2048 по короткой («best identity fidelity», в разы медленнее) | [код S1, S3] В |
| холст мода | задаёт **первая** картинка; остальные кропаются по центру под её размер (cover-crop) | [код S1] В |
| токены | на картинку `(H/32)·(W/32)`: 768² = 576; 768×1024 = 768; 1344×768 = 1008; 928×1152 = 1044; 1024² = 1024 | [код+док S1] В |
| бюджет | H3Mod Create: `max_tokens` 5120, `truncate` (сначала выкидывает почти одинаковые кадры, потом пересэмплирует). Picker: 8192. **Наш `refmod_extract_graph`: 0 + `error` — молчаливой обрезки нет** | [код S1, S2; наше] В |
| маска | вне маски латент смешивается с сильно размытой копией; `background_retention` 0…1 | [код S1] В |
| сила | `strength` (слот) × `retention` (Apply) → смесь с размытием; 0 убирает блок | [код S1] В |
| `copies` | повтор блока в `minimax_refs`. Подсказка ноды: «2–3 — sweet spot» и «внимание растёт примерно с N»; README: «не обещает пропорционального роста влияния» | [код/док S1] — **противоречие внутри источника**, С |
| `multiplier` | повтор кадров внутри мода при извлечении: то же, что `copies`, но «запекается» в файл | [док S1] В |
| кривая Apply | огибающая **по кадрам мода** (по стопке картинок), а не по времени выходного видео | [док S1] В |
| Step Curve | огибающая **по шагам денойза** (MODEL → MODEL), трогает только блоки RefMod. Ранние шаги — структура, поздние — текстура; автор не гарантирует, что это разделяет атрибуты | [код+док S1] С |
| порядок | блоки идут после штатных референсов, в порядке слотов загрузчика | [код S1] В |
| grounding | `H3 RefMod Text Encode`: декодирует латент мода и показывает его Qwen как `<Picture n>` (1 кадр) или `<Video n>` (стопка). Видео Qwen видит **с частотой 2 к/с** → у стопки из 5 картинок Qwen увидит лишь 1–2. В Picker `RefMods to Video` есть `stack_pictures` = every 4th / up to 8 / all — для стопок лучше он; он же принимает обычные картинки (плиту) через `Collect H3 References`. Не применять тот же мод второй раз через Apply | [код S1, S2] В (механика), Н (качество) |
| FL2VA и рефы | H3 Image Studio подаёт референсы и в FL2VA («both workflows start with FL2VA, including reference conditioning for editing»), REF2VA — для сравнения. `H3TextToImagePrepare` готовит **FL2VA**-условие | [док S7] С |

## 2. Чек-листы подготовки референсов

Общие правила для любого мода (для оператора и `refmod_build.py`):
- [ ] **один субъект** в кадре: чужих людей, отражений и манекенов нет [док S1 «same subject»; аналог. S9, S10] — В;
- [ ] **одинаковый аспект и размер** внутри мода: иначе срабатывает кроп по центру под первую картинку [код S1; док S2] — В;
- [ ] стороны кратны 32, короткая 512–1024 (меньше 320 H3Mod не принимает). Для лица источник — 768–1024 [код S1; наше] — В;
- [ ] без текста, водяных знаков, рамок, коллажей и листов из нескольких панелей в одном кадре: всё это переносится как контент [код S1 «preserves more information, including unwanted content»] — С;
- [ ] **без дублей и почти-дублей**: «duplicate or conflicting examples add cost without useful detail» [док S1] — В;
- [ ] резкие, без сильного шума, HDR и пересвета; свет мягкий, ровный, близкий к свету плит фермы [аналог. S9, S10; наше] — С;
- [ ] **5–10 разных кадров**: стартовая точка автора, оптимум не измерен [док S1, S2: «6–10»]; malcolmrey для персонажа — 8–20 [автор S8] — С;
- [ ] перед сохранением — `Inspect H3 RefMod`: фактическая форма латента и число токенов [док S1] — В;
- [ ] **`desc_en` на каждый мод**: 1–2 строки ключевых примет на английском, они идут в промпт. Мод в Qwen не виден, а официальный гайд описывает субъект словами даже при наличии картинки [док S5] — В.

### 2.1 Персонаж (identity)
**Лицо** (`characters/<id>/face/`):
- [ ] 1:1, 768 (лучше 1024, если исходник позволяет), голова целиком с волосами, лицо по центру, ≈ 60–70 % высоты кадра [наше; аналог. IP-Adapter Face S12] — С;
- [ ] ракурсы: анфас, 3/4 левый и правый, профили, 1–2 кадра снизу и сверху; выражения: нейтральное и улыбка. Ориентир malcolmrey: 40 % анфас, 30 % 3/4, 20 % профиль [автор S8] — С;
- [ ] **фон и одежда реально заменены на нейтральный** (у нас серый, `clean_bg`), альфа = лицо + волосы для маски [код S1; наше A] — В;
- [ ] одна основная причёска и макияж во всех кадрах. Разная причёска — «конфликтующие примеры», модель смешает [док S1; аналог. S10 «overlapping references»] — С;
- [ ] без аксессуаров, которых нет в листе персонажа (очки, серьги, головные уборы) — Н.

**Тело** (`characters/<id>/body_scale/`):
- [ ] 3:4 768×1024, полный рост целиком (стопы и макушка в кадре), без растяжения [наше] — В;
- [ ] 4–6 видов: спереди, 3/4 Л и П, сбоку, сзади [автор S8 «10 % full-body»; наше B: 4 вида] — С;
- [ ] **одна простая облегающая нейтральная одежда** во всех видах: тело задаёт форму, а одежда тела без мода одежды «прилипает» [наше B/C; сообщ. S11] — В/С;
- [ ] нейтральная поза, но не одна и та же во всех кадрах (руки вдоль тела, руки на бёдрах, полшага). Иначе возможно «залипание» позы, см. §6 [аналог. S13 copy-paste] — Н;
- [ ] фон заменён на нейтральный (у Саманты сейчас фоны «home interior», «natural background» — это протечка) [код S1] — С.

**Части тела** (`parts/`, по желанию): плотный кроп части 1:1, 512, маска части; только для проблемных частей (кисти, стопы) — С.

### 2.2 Одежда (clothing)
- [ ] 3:4 768×1024, **от шеи вниз, без лица и волос**: лицо в моде одежды тянет чужую личность [наше C; сообщ. S11] — С;
- [ ] **спереди и сзади обязательно**, плюс 3/4 по желанию (2–4 кадра); первым — вид спереди: он задаёт холст [код S1; наше] — В;
- [ ] вещь на человеке или манекене в нейтральной позе: силуэт и посадка важнее «плоской раскладки» — Н;
- [ ] фон заменён на нейтральный, альфа = силуэт одежды [код S1; наше] — В;
- [ ] одна и та же вещь во всех кадрах, без смены цвета и аксессуаров [док S1] — В;
- [ ] в строке сцены одежда **всегда и текстом** (`desc_en`): без текста база теряет низ [наше C] — В.

### 2.3 Локация / зона (background)
- [ ] **с плитой (`Picture 1`) мод зоны не нужен** [наше A; код S3 — плиту и так видят оба кодировщика] — В;
- [ ] без плиты (T2I, видео с другого ракурса): 16:9 1344×768, пустая зона без людей; 1 кадр (плита) или 3–5 ракурсов одной зоны с одинаковым светом [док S1; наше §2] — Н (что держится, а что нет, не мерил никто);
- [ ] в промпте — зона словами: ключевые предметы, их взаимное расположение, цвет и свет (`desc` карточки). Официальный пример: «`<Subject 1>` is the coffee-shop environment in `<Picture 1>`, featuring an exposed brick wall…» [док S5] — В;
- [ ] **раскладку мебели, камеру и свет мод не гарантирует**: в коде нет управления камерой, README не гарантирует точного воспроизведения [док S1]. Сообщество: в T2V локацию «досочинила» модель по тексту [сообщ. S9] — С;
- [ ] Compressed 8×8 (`style_experimental`) для зоны — только как «настроение и палитра», не раскладка [док S1 «small grid … may retain colors and large structures while losing … detail»] — С.

### 2.4 Доп. объект (generic)
- [ ] 1:1 768, предмет целиком, по центру, 3–5 ракурсов (спереди, 3/4, сбоку, сверху) [аналог. S9 «plain-background packshot … transfers more reliably»] — С;
- [ ] нейтральный фон, альфа = предмет, без рук и людей [код S1; аналог. S14 VACE salient segmentation] — С;
- [ ] в промпте — цвет, форма и материал словами: «name the colourway and the shape» [сообщ. S9] — С.

### 2.5 Стиль и поза (в ферме не используем)
- style: `style_experimental` (Compressed 8×8, 150 шагов), strength около 0.4. Экспериментально, без гарантий [док S1] — Н.
- pose_motion: только **видео** (`motion_sequence`, `ref_video`). У картинки нет движения, позу задают текст и плита [док S1] — В.

## 4. Персонаж без LoRA (раунд D)

- **Держит ли RefMod личность сам.** Механизм тот же, что у штатных референсов ref2va [код S1, S3], но через `Apply` без Qwen. Измеренных результатов нет ни у автора, ни у сообщества: автор не проводил полную генерацию для оценки качества [S1 REVIEW_FOLLOWUP]. Есть примеры «identity success» — гифки автора, не бенчмарк [S1]. Наше: с LoRA 1.5 + доработкой разница в пределах шума. **Ожидание без LoRA: лицо «похоже по типу», но слабее LoRA.** Самые сильные рычаги: grounding + текст `desc_en`, затем `copies`. Н.
- **Состав.** Лицо и тело **раздельными модами** — это позволяет выключать лицо на крупных планах без лица и держать силу тела 0.7 [наше]. Одна папка (как у Саманты сейчас) = один мод-стопка; холст задаёт первый кадр, и кропы лица 3:4 тратят токены на фон [код S1]. Разделить или нет — тест H3. С.
- **Саманта сейчас:** 12 кадров 928×1152, ≈ **12.5 тыс. токенов** в одном моде — больше всего слота Стейси. Фоны разные (комната, улица, окно) → риск протечки фона [код S1]. Профили и вид сзади полезны, но 7 кадров тела и 5 лица в одном холсте — компромисс. С.
- **Нестандартные пропорции.** Рост (230 см) моду недоступен: на нейтральном фоне ориентиров нет, а модель тянет к своему среднему. Рост держат силуэт или метка на плите и текст [наше s2]. Мускулатура и силуэт тела — видимая форма, мод её передаёт как «тип тела» (так же стабилизирует одежду), но, скорее всего, ослабит к норме модели. Источников нет. Н.

## 5. Несколько модов: порядок, веса, конфликты

- **Порядок.** Блоки идут после плиты и листа в порядке слотов [код S1]. Влияние порядка не документировано. Держим стабильный порядок `персонаж → одежда → объект → зона`, чтобы метки при grounding не прыгали [код S1 reference_map]. С (механика), Н (влияние).
- **Конфликты.** Одежда тела против мода одежды: мод одежды выигрывает, протечки нет [наше C]. Персонаж против локации: фон в рефах персонажа — главный источник протечки, лечится чистым фоном [код S1]. Одинаковые атрибуты из двух источников модель «согласует» сама, поэтому в тексте надо сказать, что берётся из какого источника: «state what each asset provides» [док S5; сообщ. S10]. С.
- **Веса.** Начальные значения автора: 1.0 / 0.7 / 0.4 / 0.15 — это маркеры H3 [док S1, S5]. Персонаж 1.0, тело 0.7, одежда 1.0. Ниже 0.4 деталь размывается [код S1]. С.
- **`copies > 1`** — только для слота, который «тонет» (лицо без LoRA). Каждая копия — полная цена [код S1]. Не больше 2–3 [док S1, автор S8]. С.
- **Бюджет.** Считать сумму токенов слота до запуска (Loader `max_total_tokens` даёт ошибку, а не обрезку) [код S1]. В.

## 6. Кадры и видео; turbo и шаги

- Механизм одинаков для кадров и видео [код S1]. В видео референс работает в каждом кадре, а «кривая» Apply — по кадрам **мода**, не видео [док S1]. В.
- Turbo и шаги. Профили Image Studio: base 20 шагов `res_multistep`/simple, shift 12; REF2VA Turbo 8 шагов `euler`, shift 12; turbo-LoRA обучены на 768p [док S7]. Модель CFG-дистиллирована [док S4]. Как turbo-LoRA взаимодействует с внешними референсами, никто не мерил. Без turbo у референса больше шагов на влияние — гипотеза H9. Н.
- T2I против ref-edit. С плитой состав и камеру держит плита, моды добавляют только субъекта. Без плиты композиция целиком из текста и модов, поэтому протечки фона и позы из рефов персонажа заметнее [аналог. S13]. С.
