## Цель (слова пользователя, сжато)
Таблица → фото продакшен-качества → зацикленное видео, **с наименьшим процентом брака и числом попыток**
(быстрее за счёт попаданий, не за счёт скорости шага). Всё внутри воркфлоу, без чата: LLM в графе (Ollama на поде)
строит сцену из строки таблицы. Позы, ракурсы и композиции сложные и разные, с предметами, с которыми персонаж
взаимодействует. Нужен 3D-вид прямо в ноде ComfyUI: двигать модели, позу, ставить предметы. H3 должен следовать
сцене точно. Переключатель моделей (H3 base / файнтюны / другие) — оставить в воркфлоу.
Результаты раунда 4 пользователю **не понравились**: мыльные локации и персонаж, простые позы — недопустимо.

## Правила
- Механизм нейтрален. По правилу фермы NSFW-промпты, таблицы, критерии и тесты ассистент не пишет и не запускает:
  тестируем на SFW-строках таблиц; NSFW-строки пользователь прогоняет сам тем же графом.
- Лицензии: всё некоммерческое — флажок пользователю (SMPL/SMPL-X, VGGFace2-веса — только как измеритель, RMBG и т. п.).
- Сначала готовая нода (скил `comfyui-workflow-json`), потом своя. Промпты H3 — скил `h3-prompt-writer`.
- Экономь токены, коммить сам в `scene3d-pilot`, в конце — STATUS/RESEARCH и блок ПЕРЕДАЧА для чата.

## Как сейчас 3D попадает в H3 (объяснить, если спросят)
1. **Референсы** (`<Picture 1>` фото локации, `<Picture 2>` лицо, RefMods/LoRA) — «что» (вид, личность).
2. **Fun ControlNet Union** (`ModelPatchLoader` + `MiniMaxH3FunControlNetApply`) — это не референс, а патч модели:
   управляющее видео (depth/pose/canny/HED/MLSD) подмешивается в блоки трансформера 0/10/20/30/40 на каждом шаге в
   окне `start..end` — «где и какой формы», попиксельно. 3D нужен, чтобы карты были в **камере фото** (MoGe-2 → плита,
   манекен 162 см ставится лучом в пиксель фото): тогда depth фото + тело на верной дистанции = место и рост 9/9.
3. Текст промпта.
Почему «приблизительно»: turbo 8 шагов (официально у Fun CN — **40 шагов, cfg 1.0**, модель guidance-distilled,
`control_context_scale` 1.0), int8-pruned патч, плоский силуэт, поза 0.5 до 50 %. Источник: comfyui-wiki, новость
2026-08-24 «MiniMax H3 Fun ControlNet Union».

## План (по порядку; каждый шаг — с листом и цифрами)
**0. Под.** Пользователь пришлёт SSH-строку нового пода. Дай ему команды по гайду студии:
`ssh -L 8188:localhost:8188 -L 8675:localhost:8675 -L 11434:localhost:11434 -L 8888:localhost:8888 root@IP -p PORT -i KEY`,
затем `/workspace/bootstrap.sh` до `УСПЕХ`; вторым окном `ssh -N -L 8189:localhost:8189 root@IP -p PORT -i KEY`.
На поде: apt-пакеты выше; `tmux new -d -s comfy_next "cd /workspace/ComfyUI-next && venv/bin/python main.py --listen 127.0.0.1 --port 8189 --extra-model-paths-config /workspace/ComfyUI/extra_model_paths.yaml --highvram --disable-pinned-memory 2>&1 | tee /workspace/logs/comfy_next.log"`;
`cd /workspace/farm/scene3d/repo && git pull`.
**1. Добрать раунд 4b** (что успело досчитаться): листы, лица, резкость A5e/A5n против A5. Коротко в отчёт.
**2. Качество без turbo** на графе build_ab, 1 Мп (1344×768), сцены P4/P8/P9 + M3_bed_sit, 2 сида:
  - Q1: ref2va base, **40 шагов, cfg 1.0**, без turbo LoRA; depth 1.0 до 100 % / до 75 %; pose 0.5 и 0.8.
  - Q2: то же на файнтюне из пульта AIO (`10Eros_Max_h3_hybrid_beta5_int8`) — проверить, что патч Fun CN грузится.
  - Q3: добавить третий контроль — **canny/HED фото** вне маски (держит мебель и текстуру комнаты), сила 0.5–1.0.
  - Q4: inpaint-режим Fun CN на **bf16-патче** (официально поддержан: 49 каналов; int8-pruned копировал дыру).
  - Метрики на каждый кадр: резкость рамки персонажа и фона (`sharpness.py`), лицо (`face_sim.py`), человек есть/нет,
    совпадение позы — DWPose (Apache-2.0) по кадру против `pose25.json` (PCK@0.05, как в пилоте 31.10).
  Критерий: резкость фона ≥ 0.8 фото, лицо ≥ 0.6, PCK ≥ 0.85, 0 пропаданий.
**3. Внедрить в AIO manual V2.2 → V2.3** (исходники UI: `workflows/aio/AIO_manual_V2.2.ui.json`,
`workflows/aio/AIO_auto_V2.2.ui.json`; движок фото: `10Eros_Max_h3_hybrid_beta5_int8` + turbo, w7 2336×1312, 2 прохода
KSamplerAdvanced, проход лица SAM3 face → FL2VA денойз 0.35): в группу «ФОТО · движок» после
`MiniMaxH3SigmaShift` вставить `ModelPatchLoader` + 2–3 `MiniMaxH3FunControlNetApply` (depth, pose, canny), входы
управления — из новой ноды 3D (шаг 4) или из `LoadImagesFromFolderKJ` на первое время; переключатель в ПУЛЬТЕ ФОТО
«3D-контроль вкл/выкл» и ручки сил/окон; турбо выкл, 40 шагов; маска вклейки — SAM3 person с генерации; дальше
штатный проход лица AIO. Тест на **SFW-строках реальной таблицы** (Confluence «Таблица Фото …», pageId 99419365 —
это NSFW-таблица Стейси: брать только SFW-строки или SFW-таблицу, которую назовёт пользователь).
**4. Ноды ComfyUI-Farm (`nodes/scene3d/`):**
  - `NGFarm3DPlate` — фото → MoGe-2 → плита (кэш по хэшу).
  - `NGFarm3DRender` — JSON сцены → bpy headless → IMAGE-батчи depth(тело)/pose/canny/mask (+ `pose25`).
  - `NGFarmSceneFromRow` — строка таблицы → JSON сцены через Ollama на поде (зона, пиксель/объект-якорь, поза из
    библиотеки, yaw, предметы); выход — тот же JSON, что у редактора.
  - `NGFarm3DScene` — **3D-вид в ноде**: начать с ядра ComfyUI `Load3D`/`Load3DAdvanced` (three.js-вьюпорт,
    .glb/.obj/.fbx, отдаёт `model_3d_info` и `camera_info`) — показать плиту фото как текстурированную сетку из камеры
    фото + манекен и предметы, двигать мышью; положение → JSON сцены. Для позы смотреть готовые ноды:
    Hina-PoseEditor3D (ComfyUI_3dPoseEditor: openpose/depth/normal/canny, обновлялся 06.2024),
    ComfyUI-3D-OpenPose-Editor2026_IK (IK только 2-звенный, лицензии нет), roborg comfyui-poser — проверить лицензии
    и пригодность; если ни одна не даёт риг MPFB + предметы + камеру фото — свой виджет поверх Load3D.
  - Библиотека поз: позы MPFB через `@reach` + импорт анимаций Mixamo (проверить EULA Adobe на коммерческое
    использование; ретаргет на MPFB в bpy). Поза из референса (`pose_ref` в таблице) — DWPose 2D → поставить в плиту
    по росту/ногам из 3D. SMPL/SMPL-X-оценщики — некоммерческие, только с флажком.
  - Автоотбраковка внутри графа: N кандидатов с разными сидами → оценка (лицо, PCK позы, человек есть, резкость) →
    лучший дальше в проход лица и видео; отчёт в StacyReport.
**5. Видео** — после стабильного фото: петля из лучшего кадра штатным блоком ВИДЕО AIO (+ pose/depth-видео из 3D,
если движение задано).
