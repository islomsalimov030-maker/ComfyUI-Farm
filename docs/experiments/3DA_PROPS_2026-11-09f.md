## Пункт 5: штатная Load3DAdvanced

GET http://127.0.0.1:8187/object_info/Load3DAdvanced подтвердил **python_module=comfy_extras.nodes_load_3d**, пакет — **ядро ComfyUI**, уже установлен. Входы model_file (COMBO из input/3d), viewport_state (LOAD_3D), width, height; выход slot1 — LOAD3D_MODEL_INFO (position/quaternion/scale, Y-up). Новых зависимостей не нужно.

Однако установленный frontend манипулирует **корнем всего загруженного GLB**, а не выбранным дочерним prop:

- MeshModelAdapter.loadGLTF возвращает gltf.scene (строка 178 исходника из sourcemap).
- SceneModelManager вызывает setupGizmo(model) (строки 623,663).
- GizmoManager.setupForModel вызывает transformControls.attach(model) (строка 106); getModelInfo сериализует трансформ targetObject. Выбора дочернего предмета / его ID в этом payload нет.
- Источник: C:/work/ComfyUI-next/venv/Lib/site-packages/comfyui_frontend_package/static/assets/load3dService-BW3CM160.js.map, встроенные исходники src/extensions/core/load3d/{MeshModelAdapter,SceneModelManager,GizmoManager}.ts; сериализация — load3dSerialize-E9pR_qlB.js.map.

Следовательно, единый GLB «локация + тело + предмет» в этой штатной ноде двигается целиком. Выдать его root transform за трансформ выбранного предмета было бы неверно.
