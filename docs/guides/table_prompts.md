# «Таблица → промпты» — промпты H3 по таблице сцен без фермы

**Что делает.** Берёт таблицу сцен фермы (xlsx) и возвращает ту же таблицу с готовыми промптами H3 в новых колонках: «Промпт кадра», «Промпт лица (кадр)», «Промпт видео», «Промпт лица (видео)», «Промпты · статус». Сборщик тот же, что у фермы: LLM пишет поля по системному промпту и JSON-схеме, промпт собирается по шаблонам H3 (тайминг, масштаб по мебели, статичная камера, свет и цвет без изменений) и проверяется линтером. Работает на любом ComfyUI, воркер и БД фермы не нужны.

**Как запустить**
1. Добавить ноду `Таблица → промпты (Next Genium)` (одна нода — это весь воркфлоу).
2. Кнопка **«Загрузить таблицу (xlsx)»** → файл таблицы (Google Sheets: Файл → Скачать → xlsx). Файл ляжет в `input/farm_tables/`.
3. **Queue**. Итог — `output/farm_prompts/<имя>_prompts.xlsx`, кнопка **«Скачать таблицу с промптами»** появится в ноде.

**Ручки**
- `only_ready` — только строки с галочкой «В работу» (выкл — все строки с ID).
- `backend` — `transformers (GPU)` (по умолчанию: модель HF на видеокарте, ~17 ГБ VRAM, порядка минуты на промпт), `llama.cpp` (GGUF прямо в ComfyUI; на студии llama.cpp без CUDA — считает на процессоре, ~12 мин на промпт) или `ollama` (+ `ollama_url`).
- `model` — пусто = модель по умолчанию для бэкенда, официальная Qwen3-VL-8B-Instruct (Apache-2.0), скачается сама в `models/LLM` при первом запуске: transformers — `Qwen/Qwen3-VL-8B-Instruct` (17 ГБ; можно имя папки в `models/LLM` или путь), llama.cpp — `Qwen3VL-8B-Instruct-Q4_K_M.gguf` (5 ГБ), ollama — `qwen3-vl:8b-instruct`.
- `fresh` — спросить LLM заново; иначе удачные поля берутся из кэша (повтор той же таблицы — мгновенно).

**Статус строки:** `ok`; `строка не прошла проверку: …` — ошибка в самой строке таблицы (как у валидатора фермы); `ошибка — <стадия>: <код>: …` — LLM не дал полей, прошедших линтер. Неудачные поля не кэшируются, повторный запуск спросит LLM снова.

Перед запуском нода выгружает модели ComfyUI из VRAM, после — выгружает LLM.

**Профили на студии (свои, вне репозитория)**

Профиль строки (колонка «Профиль») нода ищет сначала в `input/farm_profiles/` на сервере, потом в `profiles/` репозитория. Профиль из папки студии главнее одноимённого в репо.

- При первом запуске нода кладёт в `input/farm_profiles/` образец: `sfw_base.yaml` (копия профиля из репо) и его системные промпты `sfw_v1_frame.md`, `sfw_v1_video.md`. Скачать их можно по адресам `<адрес ComfyUI>/view?filename=sfw_base.yaml&subfolder=farm_profiles&type=input` (и так же для `.md`).
- Свой профиль: скопировать `sfw_base.yaml` под новым именем (`<имя>.yaml`, `name: <имя>`), поменять `content_scope`, в `llm.system_prompt` указать свои файлы `.md` — просто имена, они ищутся рядом с профилем. Загрузить файлы кнопкой **«Загрузить профиль / промпт (yaml, md)»** (можно несколько сразу; файл с тем же именем заменяется).
- В системном промпте не менять описание JSON-полей ответа (их названия и смысл) — иначе проверка отбракует ответ. Меняются правила: что и как описывать.
- Модель профиля: `llm.backend` (`transformers` / `llamacpp` / `ollama`) и `llm.prompt_model` (папка HF или файл `.gguf` в `models/LLM`). Берётся, если поле `model` ноды пустое; заполненное поле `model` — одна модель для всех строк.
- В таблице на листе «Профили» должна быть строка с этим `id`, «активен» — да; иначе проверка таблицы отклонит строки.
- В отчёте ноды видно, какой профиль откуда взят и с какой моделью. Удалённый образец сам не возвращается (нода кладёт его, только если папки ещё нет).
