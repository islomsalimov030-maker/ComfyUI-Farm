## Способы постановки позы (сравнить на одном наборе)
Набор: 12 промптов SFW возрастающей сложности (стоя вполоборота с рукой у лица; сидя на краю кровати, нога на ногу;
на коленях на кровати, руки на бёдрах; лёжа на боку, голова на руке; присед, завязывает шнурок; сидя на полу, обняв
колени; потягивается стоя, руки вверх; полулёжа, опираясь на локти; стоя, опираясь рукой о стену; на четвереньках на
коврике (йога «кошка»); сидя на подоконнике/лавке боком; стоя на одной ноге, держит другую за щиколотку).
- **A. LLM → поза.** Qwen3 (Ollama на поде/ПК, Apache-2.0) получает промпт + список костей/пределов + якоря сцены и
  выдаёт JSON: повороты костей + `@reach`-цели + контакты (`contacts: [{part: pelvis|foot.L|hand.R|knee.L|back,
  surface: "bed"|"floor"|pixel}]`). bpy применяет, решатель контактов ставит части на поверхности (raycast в плиту).
- **B. Промпт → картинка → 3D.** Z-Image Turbo (на сервере есть, Apache-2.0) рисует человека в позе (нейтральный фон,
  полный рост) → **SAM 3D Body** (ядро ComfyUI: `SAM3DBody_Loader/Predict` → `BuildPoseFile` → `SaveGLB`/`Save3DAdvanced`;
  лицензия SAM — коммерция разрешена для SAM 3, для SAM 3D Body и рига MHR проверить и записать) → ретаргет MHR → риг
  MPFB по углам суставов (длины костей наши — телосложение не меняется) → постановка в плиту + контакты.
  Модели SAM 3D Body на сервере нет (список пуст) → запуск на ПК в копии ComfyUI 0.44 (3060 Ti должна потянуть
  int8; проверить) или установка модели через Manager сервера (если он даёт), не трогая сам ComfyUI.
- **C. Референс позы** (колонка «pose_ref» таблицы): картинка → SAM 3D Body → как B.
- **D. (только тест, некоммерческие — флажок)** NVIDIA Kimodo (text-to-motion, модели RP — «non-commercial research»),
  если есть свободное время: как эталон качества, не для прода.
Метрики на каждую позу: соответствие промпту (глазами, 0/1/2), контакты (зазор/проникновение таза, стоп, кистей, колен,
см; цель ≤ 2 см), длины костей неизменны (± 1 мм), пределы суставов, затем H3-проход рецептом S3 comp2 → PCK к
плейбласту и глазами.

## Камера, ракурсы, планы
1. Исходная камера фото (по умолчанию). 2. **Планы без смены точки**: крупный/средний/общий = та же камера с
меньшим FOV (кроп плиты), генерация 1344×768 из кропа фото (апскейл) — плита и фото совпадают. 3. **Небольшие сдвиги**
виртуальной камеры (орбита ≤ 15°, наезд ≤ 0.5 м): Picture 1 = рендер плиты с фото-проекцией, дыры дорисовывает H3 —
проверить предел, где комната ещё не «плывёт». 4. **Другой ракурс** = другой кадр локации (лист ракурсов зоны) со своей
плитой MoGe. Для каждого — 2 сцены × 2 сида, лист.

## Взаимодействие с доп. объектом
Нейтральные модели (встроенные: кружка, книга, телефон, стул/табурет примитивом; или CC0-модели Poly Haven/
Kenney — лицензия в RESEARCH): держит (кисть по `@reach` к точке-ручке объекта, пальцы — хват из позы), сидит на объекте,
опирается, ставит на поверхность. Объект идёт в плейбласт, маску и тень; в промпте — `desc`. Мои предметы пользователя
из Downloads\3d_objects в тестах ассистента не использовать.
