# Предложение WS-07 → WS-00 / WS-03: слоты строки сцены (по итогам SS-340, 18.10)

Статус: **предложение**, CONTRACTS не меняет. Принимает координатор (WS-00), схему листа делает WS-03; после принятия —
CONTRACTS v0.9 (§10) и строка в `STATUS.md → Решения`. Основание — `docs/experiments/SS-340_refmod.md` §6–8.

## Что меняется в строке шота (лист «Шоты»)
| колонка | сейчас | предложение | почему (SS-340) |
|---|---|---|---|
| Персонаж | ID, один `refmod` в справочнике | без изменений в строке; в справочнике **два мода**: `refmod_body` (полный рост, одна нейтральная одежда, сила по умолчанию 0.7) и `refmod_face` (необязательный, чистые кропы лица) | мод тела держит одежду листа и пропорции; мод лица после доработки v2 выигрыша не даёт (A/A 0.72–0.78, мод +0.036 при t ≈ 1.4) |
| Наряд | необязателен («пусто можно») | **обязателен**: `desc_en` наряда всегда в промпт; `refmod` наряда — по желанию; пусто → ошибка строки `❌ Наряд` (или наряд по умолчанию из справочника персонажа, колонка `outfit_default`) | без явной одежды база теряет низ (раунды A/B/C, Standing-2); текст задаёт одежду, мод добавляет детали и одинаковость между сидами, мод тела его не перебивает |

## Справочники
- **Персонажи:** `height_cm` — **обязателен**. Сейчас сборщик берёт `defaults.height_cm: 168` (`farm/prompts/config.yaml`), QA — `scale.default_height_cm: 168`; Стейси — 162. Предложение: умолчание убрать, пустой рост → ошибка строки персонажа.
- **Наряды:** `refmod` — мод одежды из `tools/refmod_build.py` (`outfits/<id>`: от шеи вниз, без лица, серый фон, альфа = силуэт, ракурсы front + back обязательны, `concept_type: clothing`).
- **Локации:** мод зоны для кадров с плитой не нужен (плита `<Picture 1>` держит комнату, мод зоны разницы не дал); колонку `refmod` оставить для видео и других ракурсов.
- **Карточка плиты:** `horizon_y` и `camera_height_cm` становятся рабочими полями масштаба (не только справкой): ожидаемый рост стоя в долях кадра = (y_стоп − horizon_y) · рост / camera_height_cm (`farm.qa.image.scale.expected_height`). Работает на любой глубине пола, в отличие от `scale@1`, которому нужен якорь на уровне стоп.

## Масштаб (итог серии s2_scale)
Текст роста не двигает (Standing-2d, раунд C). Скелет в `<Picture 4>` H3 игнорирует. Работает только **разметка на самой
плите**: **плоский серый силуэт нужного роста в слоте** → персонаж занимает его место, рост 0.96–0.97 от 162 см
(без разметки 1.18), протечки нет. Зелёная рамка даёт тот же масштаб, но остаётся на кадре.
Предложение: строка шота → слот карточки + рост персонажа → ферма сама рисует силуэт на копии плиты (шаблон позы по классу
стоя / сидя / лежа) и добавляет правило силуэта в промпт; оператору разметка не нужна. Проверено (s2_cap, §9): обобщённая капсула без кадра-эталона на 3 плитах стоя — 9/10 в росте 0.93–0.95, без
остатка; сидя капсула навязывает прямую посадку. Поэтому: **стоя — силуэт-капсула по умолчанию**, сидя/лежа — пока без силуэта
(или позные варианты после теста). Условие — проверенные карточки (горизонт, камера, слоты): ошибка карточки = ошибка роста.
