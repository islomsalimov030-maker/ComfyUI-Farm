# Потоки работ (workstreams)

Проект делится на 10 потоков. Каждый поток — отдельный чат (или отдельный агент Claude Code на поде) со своим брифом из `briefs/`. Потоки общаются только через файлы: `CONTRACTS.md` (интерфейсы), `STATUS.md` (состояние), репозиторий `ComfyUI-Farm` (код).

## Карта

| ID | Поток | Под нужен? | Зависит от | Объём* |
|---|---|---|---|---|
| WS-00 | Координация: STATUS, решения, контракты, лицензии, интеграция | нет | — | лёгкий, по мере надобности |
| WS-01 | Аудит воркфлоу кадров и видео → «движки» для автоматики + params.yaml | для проверки | — | 2–3 сессии |
| WS-02 | Ядро оркестратора (пакет нод Farm: БД, очередь, клиент ComfyUI, профили, бандит, хранение) | нет (мок ComfyUI) | CONTRACTS | 4–6 сессий |
| WS-03 | Таблица сцен и библиотеки (Google Sheets, валидатор, карточки плит, перенос из Confluence) | нет | CONTRACTS | 2 сессии |
| WS-04 | Промпты: LLM-сборщик JSON→шаблон, линтер, системные промпты (SFW) | для прогона LLM | WS-01 (имена входов) — можно позже | 2–3 сессии |
| WS-05 | QA кадров: лицо, возраст, резкость, масштаб, руки, VLM-чек-лист | нет (CPU на готовых кадрах), GPU — для VLM | CONTRACTS | 3–4 сессии |
| WS-06 | QA видео и постобработка петли: шов, слоу-мо, камера, цвет, мерцание, ремонт шва | нет (на готовых видео) | CONTRACTS | 3 сессии |
| WS-07 | Эксперименты на поде: генераторы кадров, масштаб, модели/LoRA, RefMod, апскейл | **да** | WS-01; WS-05 желательно | 3–5 сессий пода |
| WS-08 | Telegram-бот (асинхронное ревью) | нет (мок БД) | CONTRACTS §3, §9 | 2 сессии |
| WS-09 | Ручная версия воркфлоу (маска без шва) | для проверки | WS-01 | 1–2 сессии |
| WS-10 | Интеграция и первый сквозной прогон 10 шотов на поде, калибровка порогов | **да** | все | 2–3 сессии пода |

*Сессия = один чат до ~150–200 тыс. токенов контекста.

## Волны (что делать параллельно)

```
Волна 1 (офлайн, параллельно):  WS-01  WS-02  WS-03  WS-05  WS-06
Волна 2:                         WS-04  WS-08  WS-07(под)  WS-09
Волна 3 (под):                   WS-10  → калибровка → чистка моделей/LoRA
```
Порядок, если работаем в один поток за раз: **01 → 02 → 05 → 07 → 04 → 06 → 03 → 08 → 10 → 09**. Кадры раньше видео (бриф пользователя, A4).

## Правила
- Один чат = один поток. Внутри потока можно запускать субагентов для механической работы (поиск по коду, массовые проверки), но не для решений.
- Поток может заменять соседа заглушкой по контракту и не ждать его.
- Всё, что меняет контракт, — сначала строка в «Решения» STATUS.md (через WS-00 или самим потоком с пометкой).
- Под включается только под потоки WS-07/WS-10 (и короткие проверки WS-01/09). Перед сессией пода — список задач, чтобы не платить за простой.
