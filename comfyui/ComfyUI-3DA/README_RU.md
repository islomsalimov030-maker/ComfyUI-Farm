# 3DA v1 — ручная постановка SFW в ComfyUI

**Назначение:** плита комнаты + референс позы → существующая геометрическая постановка → H3 на сервере → вклейка по карте силы. Это экспериментальный ручной инструмент, не автономная подготовка любых комнат. Подтверждённый VAE-relative гейт: R0.929515, G0 0.929515, G1 вне карты0.924494; финальная вклейка0.999985, изменённых пикселей вне карты0.

## Установка и запуск
1. Клонировать `ComfyUI-Farm`, скопировать эту папку в `ComfyUI/custom_nodes/ComfyUI-3DA`; перезапустить ComfyUI. Пак вложен в репозиторий: установка всего farm-repo в Manager **не** регистрирует автоматически вложенные ноды.
2. В отдельном farm venv поставить корневые requirements (NumPy1.26.4/SciPy1.14.1); существующий geometry env должен содержать ComfyUI с SAM3DBody/MoGe и уже скачанные модели. В env ComfyUI тяжёлые зависимости пака **не ставятся**. Blender устанавливается отдельно.
3. Исправить `config.yaml`: `repo`, `python` farm venv, `geometry_python`, `comfy` (код и модели), `farm_root` (состояние), `blender`, `mannequin` (.blend), `blender_pkgs` (существующие Pillow-пакеты Blender; YAML — отдельный .blender_site). `cell_px:16` не менять. `location_asset_dirs` связывает старый профиль с отдельно лежащими `plate.json/plate_mesh.obj/plate_rgb.png/depth_loc.png`; без него они должны быть рядом с profile.json. Секреты в config не писать.
4. В окружении **процесса ComfyUI на ПК** задать `COMFY_USER` и `COMFY_PASS` (Basic auth сервера). Не писать их в YAML/JSON, поля нод, команды с литералами или логи. В `config.yaml` секция `h3_remote`: URL `https://comfy.next-genium.com`, общий лимит ожидания `timeout_s:1800`, HTTP-таймаут `request_timeout_s:60`, интервал истории `poll_s:2`. `COMFY_URL` не переопределяет URL из YAML.
5. Открыть `workflows/3DA_manual_v1.json` **на ПК**: выбрать плиту, SFW-реф персонажа и позы; настроить Location/Place Pose, общий Seed и Queue. Геометрия работает на ПК, `3DA H3 Remote` отправляет только H3 на сервер. Локальных H3-загрузчиков больше нет. **На сервер ничего устанавливать не нужно:** используются уже доступные H3/core-ноды; геометрия, Blender и пак на сервере не нужны.
6. Установить лёгкие зависимости пака **в env ComfyUI ПК**: `uv pip install --python C:/work/ComfyUI-next/venv/Scripts/python.exe -r comfyui/ComfyUI-3DA/requirements.txt`. HTTPX нужен Remote; его наличие в отдельном farm env недостаточно. Проверено 09d: установлен HTTPX0.28.1/httpcore1.0.9 с разрешения пользователя. На сервере ничего не ставить; автоматической установки нода не делает.

## Поля и результаты
`location_id` — комната. `pose_class` — один из9 классов; `target_object` — тип **или ID экземпляра**, `instance_hint` — уточняющий id. `support_parts` — через запятую (пусто = дефолт класса), `secondary_contacts` — JSON список `{part,surface}`. `height_m` по умолчанию1.62, `body_json` — профиль тела; `proxy` grey/color (для color нужны outfit_colors), `strength`0…1, `seed` fixed. Выходы Place Pose: playblast, init (плита+тело+предметы), strength, silhouette, h3_prompt, status (флаги/опора/p95/углы/время), debug. Новые поля:
- `block_on_fail` BOOLEAN, **False по умолчанию**: статус геометрии и предупреждения не блокируют H3. True оставляет старый гейт `ok|partial`; прочие статусы дают пустой промпт. Это не отменяет ошибок CLI/невалидных входов: тогда остаются заглушки и пустой промпт.
- `body_dx/body_dy/body_dz` — метры, оси комнаты: x вправо по кадру, y вглубь, z вверх. `body_dyaw/body_dpitch/body_droll` — градусы вокруг центра таза. Нули сохраняют постановку; масштаб тела задаёт `height_m`. Это общий трансформ тела, не редактирование костей. Движок применяет трансформ после постановки и заново проверяет статус.
- `pose_text` — необязательное SFW-описание позы; движок добавляет предложение в detailed_description. Это не управление костями и не гарантия точного повторения позы H3.
- `props` — необязательный STRING JSON-список от цепочки `3DA Prop`; без подключения `[]`.

Location сохраняет слоты0–2 `location/plate/objects`; новый слот3 `objects_preview` — плита с контурами и ID поверхностей. При отсутствии preview в ответе старого CLI возвращается плита без аннотаций. В `Превью · объекты / ID` найти нужный `floor_1/surf_N/wall_N` и перенести ID в `target_object`. Старые подготовленные профили не требуют переименования.

На ПК core `StringConcatenate`: string_a соединён с генератором, string_b — ручное дополнение, delimiter пустой; Custom Scripts на ПК не нужен. В ручном серверном графе остаётся существующий Custom Scripts String с text_a/text_b/text_c. Превью raw_H3 — **до** вклейки, SaveImage — **после** core ImageCompositeMasked; вне карты сохраняется исходная плита. Перед генерацией дополнения проверить на SFW, статичную камеру, неизменный свет/цвет, отсутствие запрещённого слова из правил промптов.

## Предметы и быстрый ручной просмотр
1. Исходники пользователя лежат в `props_source_dir: C:/Users/user/Downloads/3d_objects` в source `config.yaml`. Импорт выполняется отдельным инструментом `tools/scene3d/import_props.py`, не нодой; параметры CLI см. `--help`. Поддержка форматов и нормализация — ответственность импортера/Blender. Нода не ставит пакеты, не импортирует модели и не выполняет код из моделей.
2. Библиотека всегда `<farm_root>/props/<id>/`: модель и `prop.json` с `name`, `size_m`, `description_en`, `prop_strength`. `id` — ASCII-буквы/цифры, `_`/`-`, без путей и `..`. После импорта проверить размер/материалы и заполнить пустой `description_en` по-английски (SFW). Прежде чем использовать модель в проде, проверить **её** лицензию: лицензия пака не распространяется на пользовательские ассеты.
3. Заново открыть workflow/обновить определения нод, чтобы обновился combo `prop_id`: он строится из корректных `prop.json`. При пустой библиотеке combo содержит пустую строку; включённая нода с таким выбором выдаёт ошибку вместо выдуманного предмета. В ручном UI нода `3DA Prop` по умолчанию **bypass (mode4)**; выбрать реальный id и перевести в обычный режим (mode0).
4. `anchor`: `world`, `char_head`, `char_chest`, `char_hand_l`, `char_hand_r`, `char_pelvis`. `x/y/z` — метры от якоря; **world тоже относительно центра таза тела**, по осям комнаты, не абсолютный мировой origin. `yaw/pitch/roll` — градусы. `size_m` (по умолчанию 0.30 м) задаёт самую длинную сторону bbox; импортёр `--size-m .30` сохраняет уже нормализованный GLB, а рендерер поддерживает также старый кэш. `scale` — положительный множитель поверх `size_m`. Исходный/итоговый bbox в метрах и доля проекции в кадре печатаются в debug-превью и JSON. Body/prop `out_of_frame` — доля проекции bbox <0.95, не блокировка. Предмет висит без опоры/контакта; `prop_hits_room`, `prop_hits_body`, `prop_out_of_frame` — диагностические флаги, не блокировки.
5. `prop_strength` в UI явно **0.35**. Ниже — ближе внешний вид исходной модели; выше — H3 свободнее вписывает освещение. Combo не меняет виджет динамически: если в `prop.json` задано другое значение, перенести его в поле вручную. Никаких скрытых sentinel-значений нет. При перекрытии предмета и тела движок берёт максимальную силу. С 09f2 сила больше не является прозрачностью финала: альфа склейки отдельно S>0 → дилатация16px → гаусс 8px (core ImageBlur radius8/sigma1, нормированное ядро); DifferentialDiffusion получает прежнюю карту S.
6. Для нескольких предметов соединить `props` первой ноды с optional `props_in` следующей, последний `props` — с optional `props` Place Pose. Нода только проверяет schema/числа/метаданные и собирает JSON; размещение, кэш и рендер делает CLI.

**Превью без H3:** до Queue перевести в **mute (mode2)** `3DA H3 Remote` и **все три его выходные ветки**: `Сохранить · финальная вклейка`, `Превью · raw_H3`, `Статус · H3 Remote`. Оставить активными `Превью · playblast`, `Превью · init`, `Превью · debug`, `Превью · объекты / ID`, `Статус · опора / p95 / углы`. Менять body_* / Prop и ставить Queue; seed не менять без необходимости. **Bypass Remote не заменяет mute**: pass-through может выдать плиту как будто результат. Для e2e вернуть все четыре узла в mode0. Это останавливает новую отправку, но не отменяет уже отправленную работу на сервере. Измерено09e: cache_hit=true Q01/Q04 preview19.593/19.093с; при реальной правке dx/prop yaw20.937с, без SAM/place. Цель≤15с пока не достигнута. Нода вызывает CLI, кэшируется full-precision base placement; H3 в этом режиме не вызывается. Default API JSON эквивалентен bypass UI и не содержит активного Prop; API не хранит mode4 — для предмета добавить ноду и провод явно либо экспортировать включённый UI.

## Две машины и H3 Remote
- Входы `plate`, `ref_char`, `playblast`, `init`: один RGB IMAGE (не batch); `strength`: MASK `[1,768,1344]`, 0 = сохранить фон, 1 = менять. `playblast/init` строго 1344×768; plate масштабируется серверным ImageScale как в исходном D1. `prompt` — непустой готовый SFW-текст из Place Pose + String; `seed` общий с геометрией через узел `Seed · общий для геометрии и H3`.
- Пять PNG загружаются в `input/3da_manual` через `/upload/image`, с уникальным префиксом без перезаписи. Strength — непрозрачный серый PNG → **ImageToMask/red**, не LoadImage.MASK (там инверсия alpha). Точность маски 8 бит, как у прежних PNG-артефактов.
- Копия `workflows/3DA_h3_server_api.json` заполняется **по title**, один POST `/prompt`, опрос `/history/<prompt_id>`, два GET `/view`: `final` после ImageCompositeMasked и `raw` до вклейки. `info`: status, prompt_id, total_s, upload_s, queue_and_h3_s (включает очередь).
- Любая HTTP/сетевая/валидационная ошибка → `info` начинается с `status=error` и содержит безопасный текст ответа; граф не падает. Выходы 64×64 чёрные — **не результат**; они могут сохраниться обычным SaveImage. Пустой промпт и некорректные геометрические размеры отсекаются до сетевых запросов. При `block_on_fail=False` Place Pose передаёт `h3_prompt` независимо от статуса геометрии, сохраняя флаги/status. При `True` только `ok|partial` получают промпт; остальные отсекаются пустым текстом до upload/submit Remote. При включённом гейте не добавлять string_b при rejected: ручное дополнение может сделать итоговый StringConcatenate непустым. Перед e2e всё равно проверить статус и опору; False — осознанный ручной режим, не геометрическая приёмка.
- Нет автоматических повторов submission, `/free`, глобального `/interrupt` и установки пакетов. 502 — остановиться, не перезапускать вслепую. Таймаут ожидания **не отменяет** серверную работу; проверить prompt_id/очередь перед повтором. Если POST оборвался до получения id, исход неизвестен. Не запускать одну и ту же попытку повторно без проверки.
- Лимит ожидания проверяется между HTTP-запросами; отдельный запрос может добавить до `request_timeout_s`. Загруженные PNG и серверные SaveImage остаются на сервере; автоматического удаления нет. ComfyUI-кэш может повторно использовать выход при неизменных входах: для новой попытки менять общий seed.

## Ручной режим H3 в браузере сервера
Открыть `workflows/3DA_h3_server_v1.json` на сервере. Это независимый UI-граф **без 3DA-ноды и геометрии**, с пятью LoadImage: плита, персонаж, playblast, init и strength. Выбрать PNG, вставить полный SFW-промпт в `String · промпт H3 + правки` (`text_a`; text_b/c — дополнения), задать `Движок · D1_noise/noise_seed`, Queue. Пустой text_a намеренный: не отправлять граф без собственного проверенного промпта. Итоги — два SaveImage: raw и финальная вклейка. D1 сохранён: 25 steps/euler, denoise1/always_encode, Repeat×5, 1344×768, length5; это still-тест, не FullHD-видео.

## Новая комната и статусы
Если кэша нет, существующий MoGe готовит mesh. Для новой комнаты движок может предложить геометрические поверхности `surf_N`, `floor_1`, `wall_N` и их preview. Это не семантическое распознавание мебели: `bed`/`chair` без подготовленного профиля не гарантируются. Существующие профили и `location_hints_by_id[id].seeds` (тип→XYZ метры), `footprints` с bbox/polygon в XY метрах остаются совместимыми. Явные hints — исходные данные подготовки, не догадки ноды. Для промпта требуется `profile.prompt_context.anchor` либо `prompt_context_by_location[id].anchor` — текстовый ориентир масштаба; room/action optional. Нет данных → error, доподготовить профиль. Legacy-профили без полного следа не выдают grown-top за полную маску: D4 остановлен с флагом `dominant_top_unavailable`.

| Статус | Что делать |
|---|---|
| ok | Проверить глазами, затем запускать H3 |
| partial | Проверить флаги контакта/спинки/p95; это не полная геометрическая приёмка |
| no_target / wrong_surface | Проверить тип, instance_hint, якорь/след объекта |
| contact_fail / out_of_frame | Исправить профиль/выбор позы; не ослаблять пороги |
| error | Последние30 строк stderr в status; проверить пути, модели, metadata; таймаут10мин на вызов с остановкой дерева worker/geometry/Blender |

При error сами ноды не роняют граф: выходы-заглушки и пустой промпт **не являются результатом**. Не отправлять такой граф на H3 повторно без устранения причины. SAM кэш — SHA256 PNG позы; смена PNG меняет кэш. Геометрия профиля сохраняет свой raster, H3-карты1344×768. Рост1.62 взят из рефа; VLM и Character Prep отсутствуют. Установка/полный end-to-end и ограничения конкретного запуска — в `docs/experiments/3DA_COMFY_PACK_2026-11-09d.md`. Исторический запуск09d: Q04 lie99° сохранён, contact_fail3.030см>3см блокировал H3 старым гейтом. В текущем ручном режиме этот статус сам по себе не блокирует H3 при `block_on_fail=False`; это не новый результат перепрогона Q04. Готовый локальный Q01-пульт скопирован в user/default/workflows/3DA_manual_v1.json и Downloads/3DA_COMFY_PACK_2026-11-09d.

## Ручной гизмо (09h)
Обновление10a (пак0.2.1): используйте `3DA_manual_gizmo.safe_10a` для preview. Для финала — `3DA_manual_gizmo.final_10a`, где Remote уже включён. Camera/location соединены с Prop для проверки камеры комнаты. Стандартная кнопка **«Подогнать к просмотру» / Fit** может увеличить предмет до5м и переместить камеру; это не zoom холста ComfyUI. При таком изменении новый backend выдаёт явную ошибку до H3. Восстановить камеру/размер можно повторным открытием исходного safe_10a.

Неверный предмет больше не наследует `ok` тела: out_of_frame/intersection блокируют отдельный режим H3. Тело и итоговая сцена имеют раздельную диагностику. Числовой режим сохраняется без подключения model_3d_info. Raw H3 и локальная вклейка — разные этапы; чёрный крупный план может оказаться поверхностью увеличенного предмета, даже если raw H3 нормален.

Используется готовая core Load3DAdvanced. Подготовьте локальный workflow командой `tools/build_3da_gizmo.py --help`: нужны приватный config, исходный preset, request/preview постановки и фон комнаты с телом без предмета. GLB и фон подаются штатно, перехватов GET нет. Сборщик создаёт safe preview UI/API и отдельный final API; Remote и его потребители в UI muted.

Запускайте сборщик через существующий `geometry_python` из приватного config; его NumPy/SciPy и Blender уже используются геометрией, новых зависимостей не требуется.

Соединены оба выхода гизмо `model_3d_info` и `model_3d` с Prop. При подключении числовые TRS/anchor/size_m Prop не действуют; для прежнего числового режима отсоедините `model_3d_info`. Положительный nonuniform scale поддерживается, зеркальный/нулевой — ошибка. Не нажимайте Fit to viewer и не двигайте камеру. Фон 2D не показывает окклюзии: проверяйте новый основной плейбласт после Queue. При смене комнаты/тела заново подготовьте фон и камеру сборщиком. Кэш SAM/постановки сохраняется при перемещении предмета.

Выходы PlacePose 7/8/9 подключаются к Remote как `prop_repair`/`prop_repair_mask`/`body_guides`; первые 7 индексов не изменены. Финальный preset выбирает `rendered_separately`: H3 получает только тело и комнату, затем добавляется точный рендер предмета с его depth-occluded альфой. Это предотвращает перенос референсов головы на голову персонажа. Подключённые refs предмета используются только в режиме `transfer`; в отдельном режиме они явно не отправляются, что отражено в info. Raw H3 остаётся отдельным результатом. Геометрия исходного ассета не обязана совпадать с фотографиями.

Перед открытием UI включите в Settings штатное восстановление значений по именам (`Comfy.Workflow.NamedValuesRestore`, поиск `Named Values Restore`). На проверенном frontend при позиционном восстановлении значения после force-input/converted seed могут смещаться. Этот параметр обязателен для выданного пресета. Seed=101 и fixed выставлены отдельно в PlacePose и Remote; при изменении выставьте одинаковый seed в обоих. Старые UI-файлы 09e–09g пересоберите. API-копия не зависит от UI-настройки. Не считайте общий Comfy `success` успешной постановкой без проверки `node_errors` и текстового статуса PlacePose.
