# WS-08 · Telegram-бот асинхронного ревью

**Скилы:** stacy-farm-ops. **Под:** нет (мок БД); боевой запуск — в WS-10.
**Прочитать:** CONTRACTS §3, §9; бриф пользователя раздел «З».

## Цель
Бот на поде (long polling, без входящих портов), через который пользователь и коллеги принимают кадры и видео, не останавливая конвейер.

## Шаги
1. aiogram 3 (MIT) или python-telegram-bot (LGPL) — выбрать, записать лицензию. Токен и whitelist user_id — в `/workspace/farm/secrets/`.
2. Карточка кандидата: превью (кадр — фото; видео — mp4 ≤20 МБ, иначе GIF/сжатие), шот, профиль, рука (модель+LoRA), сид, строка вердиктов проверок, номер попытки.
3. Кнопки: ✅ Принять, 🔁 Переделать, ✍️ Переделать с комментарием (следующее сообщение = комментарий), ▶️ Запустить пакет (фильтр по профилю/приоритету/ID), 📊 Статус очереди, ⏸ Пауза воркера.
4. Запись в `reviews`; оркестратор читает `consumed=false`. Уведомления пачками (не спамить: дайджест раз в N минут + срочные «нужен человек»).
5. Конфиг через YAML, чтобы позже поднять второго бота для другой команды без правки кода.

## Результат
`bot/`, тесты на мок-БД, README «как создать бота у @BotFather и запустить в tmux на поде».
**Готово, когда:** на мок-данных все кнопки меняют БД правильно; бот переживает рестарт без потери очереди уведомлений.
